01. Nexus: IPL Prediction Engine

HTML FastAPI Antigravity Docker ChatGPT Cricbuzz Redis MongoDB Railway Engagement Growth
Background

During IPL 2026, I experimented with vibe coding and AI-first development to build a functional engagement platform from scratch with zero hands-on coding experience. The goal was to ship a high-traffic MVP at zero cost during a live major sporting event, proving that product clarity and AI orchestration could collapse traditional development timelines.

Problem

Most sports platforms focus on passive consumption like viewing scores. There was a clear gap for a lightweight, real-time prediction system that could turn viewers into active participants. Most existing tools were either too complex to build quickly or failed to provide a real-time interaction loop beyond simple dashboards.

Solution

Built Nexus—a real-time IPL engagement platform featuring a match 'Arena' for live participation, a 'Squad System' for user grouping, and a real-time scoring engine with session-based predictions. The product handles complex engagement loops through gamification, points, and multipliers designed to drive stickiness.

Execution (0 → Live Product)

The project was executed using an AI-first stack (ChatGPT for PRD, Antigravity for coding, Gemini for LLM, and Railway for hosting). I followed a rapid iteration cycle: Day 1 established the foundation (Google OAuth, MongoDB), Day 2 introduced infrastructure like Redis caching, and by Day 7, we had a mature PWA with performance analytics and a real-time dashboard engine.

Outcome

Successfully shipped a fully functional live MVP in 7 days, handling real-time match scenarios during peak cricket season. The project demonstrated a zero-cost product execution model and validated the ability to ship a complete product loop without a prior technical background by focusing on high-velocity iteration.

Learnings

The experience taught me that shipping fast > planning perfect, and that AI tools dramatically compress development cycles but require absolute product clarity. Real-time systems introduce edge-case complexity early, and distribution remains the hardest problem regardless of technical speed.

02. Lume Health: AI-Native Insurance Intelligence

FastAPI Microservices AI/LLM MongoDB LLM Guardrails Antigravity
Background

A routine medical test and a subsequent warning sparked a realization about the opacity of health insurance. Confronted with the need to understand my coverage—waiting periods, exclusions, and terms—I found the process complex and time-consuming. I realized that achieving clarity during a health scare shouldn't be the hardest part of the journey.

Problem

Despite progress, nearly 44% of hospital bills in India are still paid out-of-pocket (down from 72% in 2000). The core issue isn't just a lack of insurance; it's a lack of clarity. Users lack an immediate, intuitive way to map their evolving health risks against complex, jargon-heavy insurance policies, often leading to financial surprises when care is needed.

Solution

Built Lume Health—an intelligence platform that maps personal health status to specific policy benefits. Users securely upload medical reports and insurance policies, and our AI analyzes and cross-references them in seconds to provide immediate, actionable clarity on what is covered and what isn't prior to seeking treatment.

Execution (0 → Live Product)

Architected a distributed system utilizing a FastAPI microservice backend. Leveraged Antigravity for rapid iteration and integrated a polyglot AI approach. The pipeline relies on robust LLM guardrails for secure data handling and MongoDB for persistent storage, focusing on a clean, responsive HTML frontend interface.

Outcome

Successfully deployed a functional, live MVP that validates the core health-to-policy intelligence loop. The platform is currently live, serving users while I concurrently develop additional features to expand the platform's analytical depth.

Learnings

Gained deep technical exposure to distributed systems and LLM orchestration. A significant technical milestone was implementing server-side streaming for LLM connections, dramatically improving perceived latency and user experience during complex, multi-document analyses.

03. SWARM Agentic Lab: Decentralized AI Agent Orchestration

React Vite Node.js Python LiveKit OpenCV Deepgram GPT-4o-mini MongoDB MySQL Docker Agentic AI
Background

With the rise of specialized voice-and-vision AI interfaces, there is a massive shift toward multi-agent orchestration. SWARM was built as an elite research lab and orchestration platform designed to coordinate a fleet of autonomous, real-time voice and vision AI agents, each backed by distinct database-native skill sets and mission-critical purposes.

Problem

Most conversational AI platforms are text-bound, run with high latency, or operate in complete isolation. Orchestrating a real-time, multi-modal fleet of agents (handling local biometrics, database analytics, SaaS guidance, and wellness) requires ultra-low latency audio/video routing and structured execution pipelines that don't block main loops.

Solution

Developed SWARM—a decentralized agent workspace. The fleet includes V-One (100% local biometric face verification using OpenCV DNN YuNet/SFace), Cortex BI & II (natural language SQL and NoSQL database query analysts), Nova (an autonomous SaaS copilot for UI path-finding), Lina (an empathetic voice companion for wellness), and Vigil (a structured cybersecurity auditor).

Execution (0 → Live Product)

Architected a modular microservices codebase. The frontend is built on React and Vite as an interactive command dashboard. The orchestrator runs on Node.js for token/agent dispatch, while the core intelligence layer uses a Python-based worker network. The system leverages LiveKit's SFU architecture for real-time WebRTC audio/video streams and Deepgram (Aura/TTS) for low-latency conversational speech synthesis.

Outcome

Successfully deployed a local-first multi-agent cockpit enabling sub-second latency voice/vision interactions. The platform hosts multiple concurrent specialized agents capable of running asynchronous tools, executing local deep neural network vision verification, and querying database schemas directly through natural speech.

Learnings

Learned that building human-like voice agents requires prioritizing low latency over model size, making GPT-4o-mini and LiveKit WebRTC a superior combination for high-fidelity audio loops. Furthermore, running lighter vision models (YuNet + SFace) 100% locally on ONNX eliminates API network calls and keeps user biometrics secure.
